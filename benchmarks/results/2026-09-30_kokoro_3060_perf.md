in-process (`tests/HartsyInference.Audio.Tests/KokoroBenchTests.cs`), real weights, af_heart, `EnglishG2P`
phonemes, G2P outside the timer, model load excluded.

Where the baseline went: (1) `BiLstm` ran one `LstmCell.Step` per timestep per direction — two M = 1 `Linear`
launches, an `Add`, then a host gate loop reading `gates.DataPointer`: 2884 GEMV-shaped Linears and a stream drain
per step (1552 syncs). (2) `Fft.DirectDft` (the n < 64 path) recomputed `Math.Cos/Sin` for every `k·t`: 2 · 20² = 800
transcendentals per frame, ~27 k frames each way — 650 ms. (3) ~30 host `float*` loops between device ops (style
splits, AdaLN affine, nearest upsample, depthwise convT, concats, reflection pads, residual adds, MRF average,
length regulator, PLBERT head reshapes), each a D2H sync plus an H2D re-upload; and every sub-1 MB weight (AdaIN
projections, biases, Snake alphas) re-uploaded per op because nothing preloaded (6218 small uploads).

## What changed

- Device-resident graph (no new kernels): `SliceLastDim` for gamma/beta, `LayerNormModulate` for AdaLN,
  `RepeatTime` for the nearest upsample, `ConvTranspose1d(groups = C, padLeft 1, padRight 0)` for the depthwise
  pool (PyTorch `output_padding` maps to the right crop), `Concat` (dim 1 channels, dim 2 style / reflection pad),
  `GatherRows` + `Transpose2D` for the length regulator and the text-encoder embedding, `Permute0213` for the ALBERT
  heads, `Add` / `Scale` for residuals and the MRF mean, `RepeatTime` + `Transpose2D` for the style broadcast.
  `KokoroPipeline` preloads every submodule weight once per backend and keeps the two style halves resident for the
  call. The `CloneTensor` of the shared F0/N input is gone (neither chain mutates it).
- `BiLstm`: one GEMM over the sequence for both directions' input projections (`W_ih` stacked at load), one readback,
  host recurrence (`LstmOps.RunSequence`: a dot per gate row on x86 FMA intrinsics with four accumulators and a fixed
  lane reduction, identical on the net8.0 and net10.0 builds), the two directions through `CpuParallel.For(2, …)`.
  The `W_hh` / `b_hh` tensors stay host-only. `LstmCell.Step` is untouched for `UnidirectionalLstm`.
- DSP: `Fft.DirectDft` reads a cached per-size `[n, n]` table of exactly the values it used to compute inline
  (bit-identical, `DirectDftTests`). All host fan-out goes through `CpuParallel.For` — so it honours
  `numerics.cpuThreads`, `CpuParallel.EnterInline()` and the process-wide worker ceiling — over a `FramePartition`
  whose block size depends only on the per-frame cost, never on the core count or the knob. Per-block scratch comes
  from `ArrayPool<float>.Shared`. `IStft.Apply` transforms fixed blocks of frames in parallel and keeps the
  overlap-add sequential in frame order; the STFT and the iSTFT head run fixed frame blocks. The harmonic source runs
  fixed frame blocks too: a sequential pass walks the phase accumulators through every sample with the synthesis
  loop's own arithmetic (additions and floors only) and records each block's starting phases, and each block's
  xorshift noise state is jumped to with `DeterministicRng.Advance` — so the source, the STFT and the iSTFT are all
  bit-for-bit the old single-threaded loops at any core count, any cap and inline (`NsfVocoderDspTests`), and
  streaming the source in chunks still reproduces one monolithic call exactly.
- Remaining syncs (9): duration logits (host rounding), the six BiLSTM readbacks, F0 for the host harmonic source,
  and the final spectrogram for the iSTFT.

## Expectation and evidence

Bounded, not bit-identical, and the bound is the TF32 rounding the baseline already carries. The DSP is now exact (see
above). What moves the output is precision, not algorithm: the recurrent `h·W_hhᵀ` is exact F32 on the host where
the baseline ran it as a TF32 GEMV per step, the batched input-projection GEMM groups its TF32 accumulation
differently, and the depthwise transposed conv, `LayerNormModulate` and the residual adds sum in a different order.
A recurrent prosody predictor turns that into small F0/duration differences, and the NSF source integrates F0 into
a phase, so the waveform correlation drifts (30 w per-second windows: 0.98–0.99 for 0–5 s, 0.17–0.79 for 5–10 s)
while the log-magnitude STFT correlation stays 0.97–0.998 per window, the lengths are identical and the transcripts
are identical to the baseline on all three sentences.

How large is that relative to the model's own precision noise, and is anything left once precision is taken out?
Both arms were also run with every TF32 path off (`numerics.highPrecisionGemm=true`, `numerics.noTf32=true`,
`numerics.audioConvCudnn=false` — the bench's `HARTSY_KOKORO_BENCH_EXACT=1`):

| Kokoro arm pair | 5 w | 15 w | 30 w | lengths |
|---|---|---|---|---|

| baseline default vs baseline full F32 — its own TF32 band (log-spec) | 0.9943 | 0.9857 | 0.8188 | 30 w differs (244 205 → 243 605, one duration frame) |

## Where the remaining ~170 ms goes, and the next levers

Serialized stage numbers above, 15 words (142–175 ms per profiled synth): ~65 ms of device ops (Conv1d 46.8 ms = the
vocoder's 88 convs at 0.53 ms each, everything else < 20 ms combined), ~30–40 ms of host DSP (harmonic source, STFT,
iSTFT; the "harmonic" stage also absorbs the wait for the encode/decode blocks), ~25–30 ms of host LSTM recurrence
(684 sequential steps across the six BiLSTMs, directions in parallel; the durations, f0n and textenc stages less their
device work), the rest syncs and launch gaps. In order of payoff:

1. Harmonic source + STFT + iSTFT as device kernels (the `TODO(gpu-residency)` in `NsfVocoderDsp`): ~30 → ~5 ms and
   two fewer syncs; shared with CosyVoice HiFT and RVC.
2. A fused LSTM step kernel (or a vectorized sigmoid/tanh with a stated error bound on the host path): ~25 → ~10 ms.
3. F16 / cuDNN engine selection for the 26 882-frame vocoder convs (`numerics.convChannelsLast` regime is above these
   sizes): Conv1d 47 ms is the device floor at F32.
4. CUDA-graph capture of the decoder is wall-neutral until 1–3 land (it is GPU- and host-DSP-bound, not launch-bound).

Host threading: the BiLSTM directions and the DSP blocks fan out through `CpuParallel`, so a host that lowers
`numerics.cpuThreads` (the voice host does, to keep cores for its RTP and audio threads) or runs a synthesis inside
`CpuParallel.EnterInline()` gets the same bytes on fewer cores, and the fan-out shares the process-wide worker
ceiling with every other CPU kernel. The numbers above are for one synthesis at a time at the default cap.

## Reproduce

```bash
# card must be idle: nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name --format=csv
HARTSY_KOKORO_BENCH=1 HARTSY_KOKORO_BENCH_PROFILE=1 \
HARTSY_KOKORO_BENCH_OUT_DIR=/tmp/kokoro_after HARTSY_KOKORO_BENCH_REF_DIR=/tmp/kokoro_baseline \
dotnet test tests/HartsyInference.Audio.Tests --no-build -c Release -f net10.0 \
  --filter "FullyQualifiedName~KokoroBenchTests" --logger "console;verbosity=detailed"
# shared-block A/B: same pattern with HARTSY_SHARED_BLOCK_REGRESSION=1, HARTSY_SHARED_BLOCK_OUT_DIR / _REF_DIR,
# optional HARTSY_SHARED_BLOCK_MODELS=styletts2|cosyvoice2 and HARTSY_SHARED_BLOCK_EXACT=1 (full F32);
# filter FullyQualifiedName~SharedBlockRegressionTests.
```

`HARTSY_KOKORO_BENCH_CUDA_ORDINAL` / `HARTSY_SHARED_BLOCK_CUDA_ORDINAL` (default 1) must name the 3060; the tests
fail on any other device name.
