# Kokoro per-sentence latency on the RTX 3060 — 2026-09-30

Bring-up perf pass for the phone-call voice-agent plan's Kokoro gate (15-word sentence ≤ 250 ms on the 3060,
Whisper-verify content-word recall ≥ 80 %). Branch `perf/kokoro-host-sync-loops`. Everything below is
in-process (`tests/HartsyInference.Audio.Tests/KokoroBenchTests.cs`), real weights, af_heart, `EnglishG2P`
phonemes, G2P outside the timer, model load excluded.

Where the baseline went: (1) `BiLstm` ran one `LstmCell.Step` per timestep per direction — two M = 1 `Linear`
launches, an `Add`, then a host gate loop reading `gates.DataPointer`: 2884 GEMV-shaped Linears and a stream drain
per step (1552 syncs). (2) `Fft.DirectDft` (the n < 64 path) recomputed `Math.Cos/Sin` for every `k·t`: 2 · 20² = 800
transcendentals per frame, ~27 k frames each way — 650 ms. (3) ~30 host `float*` loops between device ops (style
splits, AdaLN affine, nearest upsample, depthwise convT, concats, reflection pads, residual adds, MRF average,
length regulator, PLBERT head reshapes), each a D2H sync plus an H2D re-upload; and every sub-1 MB weight (AdaIN
projections, biases, Snake alphas) re-uploaded per op because nothing preloaded (6218 small uploads).

## What changed

- Device-resident graph (no new kernels): `SliceLastDim` for gamma/beta, `LayerNormModulate` for AdaLN,
  `RepeatTime` for the nearest upsample, `ConvTranspose1d(groups = C, padLeft 1, padRight 0)` for the depthwise
  pool (PyTorch `output_padding` maps to the right crop), `Concat` (dim 1 channels, dim 2 style / reflection pad),
  `GatherRows` + `Transpose2D` for the length regulator and the text-encoder embedding, `Permute0213` for the ALBERT
  heads, `Add` / `Scale` for residuals and the MRF mean, `RepeatTime` + `Transpose2D` for the style broadcast.
  `KokoroPipeline` preloads every submodule weight once per backend and keeps the two style halves resident for the
  call. The `CloneTensor` of the shared F0/N input is gone (neither chain mutates it).
- `BiLstm`: one GEMM over the sequence for both directions' input projections (`W_ih` stacked at load), one readback,
  host recurrence (`LstmOps.RunSequence`: SIMD dot per gate row, four accumulators, both directions in parallel).
  The `W_hh` / `b_hh` tensors stay host-only. `LstmCell.Step` is untouched for `UnidirectionalLstm`.
- DSP: cached twiddles in `Fft.DirectDft`; `IStft.Apply` inverse frames in parallel blocks before the sequential
  overlap-add; `NsfVocoderDsp` STFT / iSTFT-head frames in parallel; the harmonic source split across workers with
  the phase sum and the xorshift noise state jumped to each start (`DeterministicRng.Advance`) so the noise sequence
  is the sequential one.
- Remaining syncs (9): duration logits (host rounding), the six BiLSTM readbacks, F0 for the host harmonic source,
  and the final spectrogram for the iSTFT.

## Expectation and evidence

Bounded, not bit-identical. Sources: the batched input-projection GEMM groups its TF32 accumulation differently
from the per-step M = 1 GEMVs, and the recurrent `h·W_hhᵀ` is now exact F32 on the host (tighter than the TF32 GEMV
it replaces); the depthwise transposed conv and the residual adds sum in device order; the direct-DFT twiddles are
table values. A recurrent prosody predictor amplifies any of these into small F0/duration differences, and the NSF
source integrates F0 into a phase — so the *waveform* correlation is not the right gate for this model: it drifts
with time and with unvoiced stretches (30 w per-second windows: wave 0.98–0.99 for 0–5 s, 0.17–0.79 for 5–10 s)
while the log-magnitude STFT correlation stays 0.97–0.998 in every window and 0.988 overall, durations are identical
(same sample counts) and the Whisper transcripts are identical to the baseline on all three sentences. Floor for a
regression check on this branch: log-spectral correlation ≥ 0.98 per sentence and identical audio length.

Unit evidence: `BiLstmTests` (batched + host recurrence vs the per-step `LstmCell` on random weights, both
directions, batch 1 and 2, 1e-5 relative), `NsfVocoderDspTests` (`DeterministicRng.Advance` equals the sequential
walk at 1 / 2 / 7 / 1000 / 123 457 steps; 6-worker harmonic source equals the 1-worker one to 1e-6 with > 99 % of
samples bit-identical, noise on and off, same final phase and RNG state). Audio.Tests CPU lane 427 tests, only the
five known pre-existing failures (`AudioTextFrontendTests.{Orpheus…,Csm…}`, `EnglishG2PTests.{ToIpa…,ArpabetToIpa…}`);
Audio.Tests `Category=GpuIntegration` on the 3060 (`CUDA_VISIBLE_DEVICES=1`): 2/2.

Chatterbox, RVC) reach `NsfVocoderDsp` through `HiFTNetVocoder`. Both were run on real weights on the 3060 with
the same harness on both arms (`SharedBlockRegressionTests`, opt-in `HARTSY_SHARED_BLOCK_REGRESSION=1`; baseline

## Where the remaining ~165 ms goes, and the next levers

Serialized stage numbers above, 15 words: ~65 ms of device ops (Conv1d 47.6 ms = the vocoder's 88 convs at
0.54 ms each, everything else < 20 ms combined), ~60 ms of host DSP (harmonic 28, stft 13, istft 17), ~50 ms of host
LSTM recurrence (durations + f0n + textenc: 6 BiLSTMs, ~50 µs per step at hidden 256, dominated by the 1280
`MathF.Exp/Tanh` per step rather than the dot), the rest launch gaps. In order of payoff:

1. Harmonic source + STFT + iSTFT as device kernels (the `TODO(gpu-residency)` in `NsfVocoderDsp`): ~60 → ~5 ms and
   two fewer syncs; shared with CosyVoice HiFT and RVC.
2. A fused LSTM step kernel (or a vectorized sigmoid/tanh with a stated error bound on the host path): ~50 → ~10 ms.
3. F16 / cuDNN engine selection for the 26 882-frame vocoder convs (`numerics.convChannelsLast` regime is above these
   sizes): Conv1d 47 ms is the device floor at F32.
4. CUDA-graph capture of the decoder is wall-neutral until 1–3 land (it is GPU- and host-DSP-bound, not launch-bound).

Host threading note: the BiLSTM directions (`Parallel.Invoke`) and the DSP frames (`Parallel.For`) use the shared
thread pool for the duration of one synthesis. The numbers above are for one synthesis at a time, which is how the
audio runtime serializes requests; several Kokoro sessions in one process would share those cores and the
per-sentence wall would rise accordingly.

## Reproduce

```bash
# card must be idle: nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name --format=csv
HARTSY_KOKORO_BENCH=1 HARTSY_KOKORO_BENCH_PROFILE=1 \
HARTSY_KOKORO_BENCH_OUT_DIR=/tmp/kokoro_after HARTSY_KOKORO_BENCH_REF_DIR=/tmp/kokoro_baseline \
dotnet test tests/HartsyInference.Audio.Tests --no-build -c Release -f net10.0 \
  --filter "FullyQualifiedName~KokoroBenchTests" --logger "console;verbosity=detailed"
```

`HARTSY_KOKORO_BENCH_CUDA_ORDINAL` (default 1) must name the 3060; the test fails on any other device name.
