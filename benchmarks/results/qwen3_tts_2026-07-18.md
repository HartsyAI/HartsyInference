# Qwen3-TTS 12Hz (Qwen) — fixed "silent / driven wrong", 2026-07-18

**Verdict: custom_voice + voice_design now word-perfect. The bug was tokenization, not the engine — the
extension padded the text stream to 512 tokens.**

The STT reality-check flagged Qwen3-TTS as silent / "probably driven wrong." Root cause found by running the
1.7B-CustomVoice checkpoint end-to-end with `QWEN3_DEBUG=1`: the talker generated fine, but the audio was
**32.7 s for a ~4 s sentence** (garbage-length).

## Root cause
`Qwen3TtsModel` (extension) tokenized with `Qwen3Tokenizer.Encode(text, appendEos:false)`, which:
1. **right-pads to `maxLength` (512)** with `<|endoftext|>` — a diffusion text-encoder convention, wrong for
   TTS. `BuildPrefill` pairs every text token with `codec_pad`, so ~500 padding tokens flooded the talker's
   text stream → the model ran far too long on a malformed prefill.
2. skips GPT-2 **byte-level** pre-tokenization (drops leading spaces: `" there"`→`"there"`), so even the real
   tokens were subtly wrong.

The engine already exposes `Qwen3Tokenizer.EncodeRaw` (byte-level, no padding/EOS) for exactly this.

## Fix (extension one-liner)
`Qwen3TtsModel.cs`: `tokenizer.Encode(req.Text, appendEos:false)` → `[.. tokenizer.EncodeRaw(req.Text)]`.
The engine pipeline (talker + MTP + Snake/ConvNeXt vocoder) was already correct.

## voice_clone (x-vector) — implemented + verified 2026-07-18
The Base checkpoint's `x_vector_only` clone path now works end-to-end. Reference: `github.com/QwenLM/Qwen3-TTS`
`qwen_tts` (`generate_voice_clone` / `generate`). x_vector_only mode = the normal prefill with the reference
clip's **ECAPA speaker embedding injected at the codec speaker position** (in place of a preset-speaker token) —
no ICL block, no codec encoder needed.

Work:
- **Rewrote `EcapaSpeakerEncoder`** to match the real `speaker_encoder.*` layout — the prior port assumed a
  SpeechBrain-with-BatchNorm topology that didn't match. Qwen3's is a **no-BatchNorm** ECAPA: TDNN stem
  (`blocks.0`, Conv1d+ReLU) → 3 SE-Res2Net blocks (`blocks.1..3`: tdnn1 → nested Res2Net (chunk×scale=8,
  cascaded k3 TDNNs) → tdnn2 → SE via `conv1`/`conv2` on the time-mean → +residual) → MFA (concat SE-Res2
  outputs → `mfa.conv`+ReLU) → attentive stats pooling (`asp.tdnn`+ReLU → tanh → `asp.conv` → softmax) →
  `fc` (Conv1d 3072→2048). Ends at `fc` (no post-projection). Output enc_dim 2048 == talker hidden.
- **128-bin log-mel front-end** (n_fft 1024 / hop 256 / win 1024, slaney filterbank, fmin 0 / fmax 12000,
  magnitude, `log(clamp(x,1e-5))`) via `MelSpectrogramExtractor`.
- **Prefill injection**: `BuildPrefill` places a sentinel at the speaker position; `GenerateFromPrefill` adds
  the raw ECAPA embedding there (text side = tts_pad), per the reference `codec_input_embedding = [control,
  speaker_embed, codec_pad, codec_bos]`.

Verified (Base 1.7B, RTX 3060): whisper word-perfect ("…test of the Quen speech synthesizer.", 3.76 s), and
the clone **responds to the reference** — cloning from two different speakers gives essentially uncorrelated
outputs (waveform corr 0.01, different length/loudness), confirming the x-vector drives the voice. Harness
`<scratchpad>/q3bench/` (`Q3_MODE=voice_clone`). Extension `Qwen3TtsModel.cs` wired: loads ECAPA for the Base
model, calls `SynthesizeVoiceClone` with `req.ReferenceMono24k`.

Not implemented: the higher-quality **ICL mode** (`x_vector_only=False`) — needs porting the Qwen3-TTS-Tokenizer
codec *encoder* (16-codebook, to seed the codec context with the reference's codes) + the ref-text interleave.
x-vector (timbre) cloning is the shipped mode.
