# Zonos-v0.1 (transformer) — autoregressive-decode perf pass (2026-07-17)

Text → 44.1 kHz speech, pure-C# `ZonosPipeline` (ResNet293 speaker encoder + 7-conditioner prefix + 26-layer
GQA backbone + delayed-AR over 9 codebooks + DAC decode). Voice-clone TTS: a reference clip conditions the voice.
This pass is a **decode-speed** optimization — correctness was already verified (greedy codes bit-parity vs upstream;
see the Zonos row in [`../../docs/Checklists/MODEL_STATUS_AUDIO.md`](../../docs/Checklists/MODEL_STATUS_AUDIO.md) and
[`../../docs/Checklists/PARITY_VERIFICATION.md`](../../docs/Checklists/PARITY_VERIFICATION.md)). GPU = RTX 4090
(engine `CudaBackend`, **F32** — TF32 degenerates over the AR loop, so F32 is a deliberate correctness choice).
A frame = 512 samples @ 44.1 kHz ≈ **11.6 ms** of audio, so real-time is 11.6 ms/frame.

| Path | Before | After | ms/frame (before → after) | RTF |
|---|---|---|---|---|
| **Full stochastic engine** (min-p + rep-penalty + CFG) | ~203 ms/fr | **~32 ms/fr** | 203 → 32 (**~6.3×**) | 17.5× slower → **2.9× slower** than real time |
| **Greedy golden-prefix bench** (200 frames) | ~106 ms/fr | ~36 ms/fr | 106 → 36 (~2.9×) | — |
| **Production Swarm gallery gen** (`GenerateText2Image`) | — | 444 fr / 15252 ms = **~34 ms/fr** | — | 2.9× slower than real time |

Headline: **~6× faster (203 → 32 ms/frame stochastic)** with correctness preserved — greedy stays bit-parity, and
the production gallery clip transcribes verbatim (Whisper medium.en: *"The resident decode path makes Zonos six
times faster while sounding identical."*).

## What moved the number (203 → 32 ms/frame, ~6×)

The entire attention block ran **host `Buffer.MemoryCopy`/loops on GPU tensors** (`DiaAttention.SelfForward` +
`StreamingKvCache`): host interleaved RoPE (`DiaWeights.RopeInterleavedInPlace`), host head reshapes
(`DiaHeads.FlatToHeads`/`HeadsToFlat`/`RepeatKv`/`SliceLeading`), and a host KV append. Each host op broke the CUDA
activation-residency cache → per-op H2D/D2H round-trips + an **O(n²) re-upload of the growing K/V cache every step**
(the GQA `RepeatKv` replication made it worse). SYNC-mode profile before: SDPA ~40% (inflated by re-uploading the
GQA-replicated K/V), Linear ~26%, H2D_MISS ~22%.

Fix: a **GPU-resident decode path** mirroring the LLM package's `GenericTransformer` (Zonos-only; the host
`DiaAttention.SelfForward` used by Dia is UNCHANGED):

- New `DiaAttention.SelfForwardFlash` — Q/K/V `backend.Linear` project straight into head-shaped `[1,t,H,d]`
  tensors (no host reshape) → `backend.ApplyRopeInterleaved` (GPU rope) → `backend.Permute0213` →
  `FixedKvCache.AppendStep` (GPU in-place `KvCacheAppend`) → GQA-native `backend.FlashAttention(kvLen, group,
  causal, qOffset)` (no K/V replication; reads the resident cache buffer with a valid length).
- `ZonosBackbone.ForwardResident` / `ZonosBlock.ForwardResident` + a per-forward GPU rope-slice `[1,t,headDim]`.
- `ZonosPipeline` now uses `FixedKvCache` (`HartsyInference.LLM.Transformer`, in-place GPU append) instead of
  `StreamingKvCache`, gated on a new capability flag **`IBackend.FlashDecodeSupported`** (CudaBackend → true;
  CPU/Vulkan → false and keep the host path).
- MLP keeps its host SwiGLU — a small, non-cascading per-layer cost.

Profile after (SYNC): **`H2D_MISS` dropped 1059 → 213 ms**, and the SDPA / K-V-re-upload cost is eliminated. The
decode is now **GPU-compute-bound on F32 Linear GEMVs** (~1573 ms in the SYNC profile). Launch overhead is
negligible (non-sync wall ≈ sync wall), so a CUDA-graph capture would add little here — unlike the launch-bound
small TTS/STT models. The next lever is **F16 weights**, but that is RISKY and untested (F32 is deliberate — TF32
degenerates over the AR loop); speaker-encoder host syncs + the MLP host-SwiGLU are minor follow-ups.
